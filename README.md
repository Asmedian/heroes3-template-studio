# Heroes III Template Studio — GitHub Pages / PWA

**Версия:** 1.0.1 · **Основа:** [sokie/heroes3-template-util](https://github.com/sokie/heroes3-template-util), Python CLI / PySide6 редактор, MIT. Это **самостоятельная браузерная реализация**, а не сборка исходного PySide6 приложения. Из предоставленного пользователем архива использована версия коммита `e0143ce06d5cb8d616d5facd4e05569437878a07` (проект `h3tc` v0.3.0). Исходная лицензия включена в `LICENSE`.

## Возможности

- Чтение, редактирование, сохранение и взаимная конвертация **SoD (`.txt`), HotA 1.7.x (`.h3t`), HotA 1.8.x (`.h3t`)**; точные схемы: 85 / 138 / 140 колонок соответственно.
- Локальная обработка файлов **без загрузки на сервер**; UTF-8, UTF-8 BOM, Windows-1251, Latin-1; сохранение исходных байтов без изменений, если шаблон не редактировался.
- Несколько карт в пакете, поиск и переключение карт; создание / дублирование / удаление карты, зоны, связи; инспектор свойств карт, зон, связей и пакета, включая расширенные поля HotA.
- SVG-редактор: перемещение зон и холста, колесо мыши / кнопки масштабирования, **масштабирование двумя пальцами на телефоне**, «Вместить», новая связь двумя кликами или **Alt + drag**, авторасстановка и раздвижение / сближение, перенумерация ID с обновлением ссылок и совместимых подсказок (`hint`).
- Отмена / повтор, проверка дубликатов и некорректных связей, предупреждения о потере данных при конвертации, экспорт схемы в PNG.
- Совместимый с оригинальным редактором экспорт **многокартового** sidecar `имя_шаблона.h3t.h3tc-layout.json` или `имя_шаблона.txt.h3tc-layout.json`; импорт sidecar, в том числе более старого однокартового формата веб-версии. Для HotA изменённые координаты включаются в поля `image_settings` при сохранении; SoD хранит схему только в sidecar.
- Тёмная / светлая темы, адаптивная компоновка, drag-and-drop файлов, горячие клавиши, устанавливаемое PWA с собственными manifest, значками, offline service worker и механизмом обновления кэша по версии.

**Ограничения веб-платформы:** приложение не имеет прямого доступа к произвольным локальным файлам / системному «Недавние файлы» Windows и не запускает нативный PySide6. Сохранение вызывает загрузку файла браузером. Автоматическая сортировка / дополнительные темы GUI могут отличаться по отображению от оригинала. `LocalStorage` для запоминания координат конкретных файлов — вспомогательное хранилище, а не замена экспортируемому sidecar.

## Опубликовать на GitHub Pages

1. Создайте GitHub-репозиторий и загрузите **содержимое этой папки** в корень ветки `main` — файл `index.html` должен находиться в корне репозитория. Включая скрытую папку `.github`.
2. В GitHub откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Сделайте `push` в `main` или запустите **Actions → Test and deploy H3 Template Studio → Run workflow**. Задача `unit` выполняет Node-тесты, `browser` устанавливает Playwright Chromium и проводит smoke-тест, 13 адаптивных разрешений (тёмная и светлая темы) и расширенные проверки мобильных жестов/PWA, `deploy` публикует сайт только после успеха обеих.
4. Страница откроется на `https://<account>.github.io/<repository>/` (или на корневом домене user/org pages). **Никаких абсолютных `/`-путей для ресурсов** не используется: файлы работают в подкаталоге GitHub Pages.
5. Откройте сайт через HTTPS и нажмите **«Установить»**. В Chrome/Edge браузер покажет системный запрос на установку, когда выполнены его критерии. В iOS Safari: «Поделиться» → «На экран Домой». Если `beforeinstallprompt` не поддерживается, кнопка выводит соответствующую инструкцию.

Не открывайте `index.html` через `file://`: для ES modules, Fetch и service worker необходим HTTP(S). Сайт работает без сборщика и без backend, GitHub Actions просто копирует статические ресурсы в Pages.

**Важно о публикации тестовых данных.** Папки `samples/` и `tests/fixtures/` содержат три переданных для тестирования шаблона. При публикации репозитория или GitHub Pages они становятся доступны третьим лицам (workflow публикует только `samples/tesseract.txt`). Перед созданием публичного репозитория проверьте права на их распространение; если разрешение отсутствует, удалите соответствующие файлы из публичной копии, адаптируйте тесты и оставьте собственный разрешённый демо-шаблон `samples/tesseract.txt`.

## Локальный запуск

**Предварительные условия:** Python 3, Node.js 20+ (Node нужен **только** для тестов), современный браузер.

```bash
cd h3tc-web
python3 -m http.server 8000
# Open http://localhost:8000
```

```bash
npm test
# Optional real-browser E2E test; requires access to Playwright's browser downloads:
python3 -m pip install playwright==1.57.0 pillow
python3 -m playwright install chromium
python3 tests/browser_smoke.py
python3 tests/browser_responsive.py
python3 tests/browser_interactions.py
```

`npm test` не требует `npm install`, так как использует встроенный тест-раннер Node.js и не имеет JS-зависимостей.

## Использование

1. При запуске открывается XXL Tesseract (демо SoD). Нажмите **«Открыть»** или перетащите `.txt`/`.h3t` на окно редактора.
2. Слева переключайте карты; в центре увеличивайте, перетаскивайте и редактируйте схему; справа изменяйте параметры выбранной карты / зоны / связи. «Настройки пакета» открывают метаданные HotA.
3. «Сохранить» записывает исходный формат, «Конвертировать» — целевой из списка. При несовместимых полях появляется предупреждение; **источник не перезаписывается**.
4. Для визуальной схемы используйте «··· → Сохранить позиции всех карт». Сохраните sidecar рядом с шаблоном для открытия в исходном Python GUI. «Загрузить позиции» импортирует sidecar, сопоставляя карты по именам.
5. Для HotA при изменении расположения и сохранении исходного файла `image_settings` обновляется автоматически. Для SoD экспортируйте sidecar отдельно.

**Горячие клавиши:** Ctrl+O — открыть, Ctrl+S — сохранить, Ctrl+Z / Ctrl+Y — отмена / повтор, Ctrl+0 — вместить, Ctrl+Shift++ / Ctrl+Shift+- — раздвинуть / сблизить, Delete — удалить выбранное, Escape — выйти из режима создания связи / закрыть панели.

## Тесты и проверенные шаблоны

- `tests/core.test.mjs` — схемы, кодировки, TSV с экранированием, безызменный байтовый roundtrip, изменённый семантический roundtrip, конвертация, диагностика потерь, ID / hint / ссылки, геометрия.
- `tests/sidecar.test.mjs` — JSON sidecar всех карт, соответствие формату Python, фильтрация зон и импорт.
- `tests/upstream_parity.py` — **поле за полем** сравнивает полученные браузерным движком модели со встроенными Python-парсерами исходного репозитория. Требует отдельную копию исходников и `pydantic`:

  ```bash
  python3 tests/upstream_parity.py --upstream-path /path/to/heroes3-template-util
  ```

- `tests/browser_smoke.py` — реальный Chromium: загрузка трёх файлов, схемы, редактор, масштаб, темы, сохранение, конвертация, PNG, манифест и offline.
- `tests/browser_responsive.py` — 13 размеров от 320×568 до 2560×1440, включая портретные/альбомные телефоны и планшеты; обе темы, проверка доступности всех кнопок, поиск карт, боковые панели и снимки экрана.
- `tests/browser_interactions.py` — интерактивные проверки PWA, команды, PNG, 126 карт, вложенный путь GitHub Pages, установочный запрос, офлайн-режим, pinch-to-zoom и сенсорное перемещение.

Тестовый охват: XXL Tesseract — 1 карта, 16 зон, 32 связи; Duel — 30 карт, 270 зон, 420 связей; Jebus Outcast — 126 карт, 962 зоны, 2216 связей. **В самом исходном Duel** имеются обрезанные строки связей и 420 неподключённых строк; они читаются без автоматического исправления и отображаются в диагностике. Не интерпретируйте отсутствие связей у части этих строк как баг визуального редактора.

## Структура

| Файл / каталог | Назначение |
|---|---|
| `index.html`, `styles.css` | интерфейс и темы |
| `src/core.js` | форматный движок, TSV, кодировки, конвертация, валидация |
| `src/schema-data.js`, `src/schema.json` | схемы, экспортированные из Python upstream |
| `src/layout.js`, `src/sidecar.js` | раскладка SVG, `image_settings`, совместимый sidecar |
| `src/app.js` | логика веб-редактора, drag/drop, PWA install |
| `manifest.webmanifest`, `sw.js`, `public/icons/` | PWA и автономная работа |
| `.github/workflows/deploy.yml` | unit + browser E2E + Pages deployment |
| `scripts/export_schema.py`, `scripts/bump_version.py` | обновление схемы и версий |
| `tests/` | unit / E2E / upstream differential tests |
| `UPSTREAM_UPDATE.md` | отдельное руководство по синхронизации с sokie |
| `TEST_REPORT.md` | проверенные разрешения, тесты, найденные исправления и ограничения |
